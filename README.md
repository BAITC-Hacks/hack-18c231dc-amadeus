# Аким на 5 часов

Расчётный движок симулятора управления городом на Python и HTTP API на FastAPI. Задание —
[docs/task.md](docs/task.md), исходный датасет и формула —
[docs/dataset.md](docs/dataset.md).

Все районы, показатели, веса, 14 мер, синергии и несовместимости хранятся в
[data/city.json](data/city.json). Движок использует стандартную библиотеку Python;
FastAPI и uvicorn обеспечивают HTTP API, pytest и httpx нужны для тестов.
AI-объяснение доступно через `/api/explain`; React-интерфейс подключён к HTTP API.
Запуск интерфейса и сценарий работы — [docs/frontend.md](docs/frontend.md).

## Как запустить тесты

Из корня проекта (Python 3.10 или новее):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
```

В Windows для активации окружения в PowerShell используйте
`.venv/Scripts/Activate.ps1`.

## Использование движка

```python
from engine.validator import validate
from engine.simulator import simulate

decisions = [
    {"measure_id": "M7", "district": "Нура"},
    {"measure_id": "M8", "district": "Нура"},
    {"measure_id": "M10", "district": "Нура"},
    {"measure_id": "M12"},
    {"measure_id": "M5", "district": "Сарыарка"},
]

errors = validate(decisions)  # [] — набор валиден; иначе список причин на русском
if errors:
    print(errors)
else:
    result = simulate(decisions)
    print(result["Score"])  # 56.54307; стоимость 95

baseline = simulate([])  # Score = 52.55768; N_crit = 2
```

`simulate()` не вызывает валидатор: базовый сценарий и промежуточные наборы
можно считать отдельно. Для пользовательского набора сначала вызовите `validate()`;
он требует ровно 5 мер. Для городской меры поле `district` нужно полностью опустить
(даже `null` считается указанным полем). Неизвестные меры или районы, а также
отсутствующий район районной меры при прямом вызове `simulate()` вызывают `KeyError`.

Результат `simulate()` — словарь:

| Ключ | Значение |
|---|---|
| `indicators` | Новые показатели: район → код показателя → значение |
| `D` | Район → взвешенная оценка района |
| `D_avg` | Средняя оценка с учётом долей населения |
| `D_min` | Минимальная оценка района |
| `N_crit` | Число пар «район × показатель» со значением строго меньше 40 |
| `Score` | `0.7 × D_avg + 0.3 × D_min − N_crit` |
| `cost` | Суммарная стоимость выбранных мер |

Эффекты масштабируются по лагу, синергии начисляются без масштабирования в район
указанной в JSON меры. Ограничение показателей диапазоном 0–100 выполняется после
суммирования всех эффектов и синергий. Промежуточные и итоговые числа не округляются.
Порядок решений не влияет на результат; исходные данные и входной список не изменяются.

Контрольные результаты:

| Сценарий | Стоимость | D_avg | D_min | N_crit | Score |
|---|---|---|---|---|---|
| Пустой набор | 0 | 56.8624 | 49.18 | 2 | 52.55768 |
| Пример из датасета | 95 | 58.0776 | 52.9625 | 0 | 56.54307 |

Тесты проверяют контрольные сценарии, правила валидатора, все три синергии,
лаг и область действия мер, отрицательные эффекты, границы показателей,
независимость от порядка решений и загрузку каталога из JSON.


## Как запустить API

После создания и активации окружения из раздела «Как запустить тесты» установите
зависимости и запустите сервер из корня проекта:

```bash
python -m pip install -r requirements.txt
uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

API доступен на `http://127.0.0.1:8000`, Swagger — на
`http://127.0.0.1:8000/docs`. CORS разрешён для `http://localhost:5173` и
`http://localhost:3000` через
[CORSMiddleware](https://fastapi.tiangolo.com/tutorial/cors/).

Получить конфигурацию:

```bash
curl http://127.0.0.1:8000/api/config
```

`GET /api/config` возвращает `budget`, `horizon`, `horizon_unit`, `districts`
(словарь по названиям районов с `population_share` и исходными `indicators`),
`indicators` (список с `id`, `name`, `direction`, `description`, `weight`),
`measures`, `synergies`, `incompatibilities`, `rules`, `scoring` и `baseline_score`.
Базовый Score каждый раз получает из движка через `simulate([])`.

Рассчитать сценарий:

```bash
curl -X POST http://127.0.0.1:8000/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"decisions":[
    {"measure_id":"M7","district":"Нура"},
    {"measure_id":"M8","district":"Нура"},
    {"measure_id":"M10","district":"Нура"},
    {"measure_id":"M12","district":null},
    {"measure_id":"M5","district":"Сарыарка"}
  ]}'
```

Для городских мер API принимает `district: null` или отсутствие поля. Перед
передачей в валидатор поля со значением `null` удаляются. Районная мера без района
остаётся невалидной. Правила и расчёты движка не изменены.

Валидный запрос возвращает HTTP 200 и следующие поля без округления:

| Ключ | Значение |
|---|---|
| `valid` | `true` |
| `cost`, `remaining_budget` | Стоимость и остаток бюджета: в примере 95 и 5 |
| `Score`, `baseline_score`, `score_delta` | Итог 56.54307, база 52.55768 и изменение 3.98539 |
| `D_avg`, `D_min`, `N_crit` | Средняя оценка, минимальная оценка района и число критических показателей |
| `synergies` | Сработавшие пары: `measures`, `target_measure`, `effects` и район `district` |
| `districts` | Словарь по названиям районов с `D_before`, `D_after` и `indicators` |

Внутри `districts[район].indicators[код]` находятся `before`, `after`, `delta`.
Например, для `Нура` → `S1`: `{"before": 38, "after": 48, "delta": 10}`.

Нарушение правил набора возвращает HTTP 200 с
`{"valid": false, "errors": ["причина на русском"]}`. Расчёт в этом случае
не запускается, поля Score нет. Некорректная структура запроса (например,
отсутствие `decisions` или обязательного `measure_id`) возвращает HTTP 422.

Общий запуск тестов `python -m pytest -q` проверяет движок и API.


## AI-объяснение результата

Все числа считает только движок. OpenAI получает готовые факты и объясняет их
на русском; модель не участвует в расчёте Score. Существующие `/api/config` и
`/api/simulate` работают независимо от наличия ключа.

Создайте файл `.env` в корне проекта по образцу `.env.example` и заполните:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=идентификатор_модели
```

Укажите доступную вашему аккаунту модель с поддержкой Responses API и
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
В `.env.example` оба значения пустые. Ключ не хранится в коде; `.env` исключён
из Git. `python-dotenv` загружает файл при запуске сервера; переменные окружения
имеют приоритет. После изменения `.env` перезапустите сервер.

Установите обновлённые зависимости и запустите API:

```bash
python -m pip install -r requirements.txt
uvicorn api.main:app --reload --host 127.0.0.1 --port 8000
```

Запрос принимает только решения. Стоимость, Score и другие числа от клиента
не принимаются: сервер заново валидирует и рассчитывает сценарий.

```bash
curl -X POST http://127.0.0.1:8000/api/explain \
  -H 'Content-Type: application/json' \
  -d '{"decisions":[
    {"measure_id":"M7","district":"Нура"},
    {"measure_id":"M8","district":"Нура"},
    {"measure_id":"M10","district":"Нура"},
    {"measure_id":"M12","district":null},
    {"measure_id":"M5","district":"Сарыарка"}
  ]}'
```

Для валидного набора ответ содержит `valid: true`, `ai_generated`, `summary`
(два или три предложения), `strengths`, `risks`, `consequences`, `recommendations`
(списки коротких пунктов), а также `contributions`.

Вклад каждой меры рассчитывается как **Score полного набора − Score набора без
этой меры**. В `contributions` находятся `measure_id`, `district`, `score_without`
и `contribution`. Наборы без одной меры передаются прямо в `simulate()`, без
валидатора. Вместе с мерой исчезают зависящие от неё синергии. Вклады не обязаны
складываться в общий прирост Score из-за минимальной оценки района, штрафов и
синергий. Формулы движка не изменены.

Модель получает компактный JSON: выбранные меры и районы, цены и лаги, Score и
базовый Score, оценки районов до и после, показатели и их изменения, критические
значения до и после, сработавшие синергии, вклады, остаток бюджета, каталог и
правила. Дополнительно сервер готовит до трёх допустимых одиночных замен из
каталога, проверяя каждую валидатором. Это отдельные варианты для сравнения,
не оптимизированные сценарии: их Score не рассчитан, улучшение не обещается.
Промпт запрещает модели придумывать числа, пересчитывать Score или предлагать
замены вне этих вариантов.

Ответ модели запрашивается через Responses API с `json_schema`, `strict: true`
и повторно проверяется по той же схеме на сервере. Успешный ответ отмечается
`ai_generated: true`. При отсутствии ключа или модели, ошибке OpenAI, тайм-ауте,
отказе или некорректном ответе возвращается локальный шаблон с
`ai_generated: false`: наиболее полезная мера по вкладу, самый слабый район,
оставшиеся критические значения и лаги. Ошибки сервиса и ключ клиенту не передаются.

Невалидный набор возвращает HTTP 200 с `{"valid": false, "errors": [...]}`
без расчёта и без обращения к OpenAI. Тесты `tests/test_explain.py` подменяют
клиент OpenAI; реальных запросов и расходов при `python -m pytest -q` нет.


## Анализ всех сценариев

Полный перебор запускается из корня проекта и не обращается к OpenAI:

```bash
python scripts/precompute_scenarios.py --workers 4
```

Скрипт рассматривает каждую комбинацию пяти уникальных мер и все назначения
районов для районных мер. Городские меры не требуют района. До назначения районов
отбрасываются только превышение бюджета, превышение лимита направления и глобальные
несовместимости; каждый оставшийся набор проверяется штатным `validate()` и каждый
допустимый набор рассчитывается штатным `simulate()`. Порядок решений не создаёт
дополнительный сценарий. Формулы движка не меняются.

Результат записывается атомарно в `data/scenario_stats.json` (до 1 МБ):
`valid_scenario_count`, `baseline_score`, `best_scenario`, `top_5` и 1001 квантиль
от 0 до 100% с шагом 0.1 процентного пункта. `best_scenario` и каждый элемент
`top_5` содержат `decisions`, `Score`, `cost`. Файл также хранит отпечаток датасета.
Эмпирические квантили используют нижнюю порядковую статистику; для каждого узла
сохранены числа результатов строго ниже и не выше его Score.

Для валидного набора `/api/simulate` дополнительно возвращает:

| Поле | Смысл |
|---|---|
| `best_possible_score` | Максимум среди всех допустимых наборов |
| `gap_to_best` | Максимум минус Score текущего набора |
| `percentile` | Приблизительно сколько процентов допустимых наборов имеют строго меньший Score |
| `warnings` | Новые критические значения: `measure_id`, `district`, `indicator`, `before`, `after` |

Процентиль оценивается интерполяцией между квантилями; равные результаты в самих
узлах не считаются худшими. Это сравнение с синтетическими допустимыми сценариями,
а не рейтинг реальных участников. Новое критическое значение — переход от значения
не ниже 40 к значению ниже 40 после всех эффектов. В предупреждении указана районная
или городская мера с отрицательным эффектом на этот показатель. Если другие меры
компенсировали снижение и итог не ниже 40, предупреждения нет.

Те же поля возвращает `/api/explain`; они передаются модели и используются локальным
шаблоном. При отсутствии статистики или изменённом датасете три поля сравнения
равны `null`, обычный расчёт и предупреждения продолжают работать. После изменения
`data/city.json` повторите команду перебора. HTTP-запросы полный перебор не запускают.
